ZAPRET CONTROL 1.5.0 — RTC И ПРИЁМ ЭФИРА
1 ноября 2026

ЧТО ИСПРАВЛЕНО В ПРОГРАММЕ

1. Удалён перехват всего исходящего UDP из широких диапазонов RTC.
   RTP / RTCP, включая обратную связь при просмотре эфира, не отправляются
   в пользовательский обработчик ни во входящем, ни в исходящем направлении.
   Служебные Discovery / STUN / DTLS остаются доступны на любых UDP-портах.
   QUIC Initial для сайтов на UDP 443 распознаётся отдельно по длинному заголовку.
2. Удалено старое правило неизвестного UDP, которое отправляло фейки для первых
   пакетов по списку адресов без подтверждения служебного протокола.
3. Режим RTC теперь определяет не только UDP-фейки, но и TLS-сигнализацию
   discord.media. Перебор одного только UDP не менял этот путь в старой версии.
4. Исправлен пропуск ошибок, когда NO_ROUTE и последующее DISCONNECTED
   появлялись в одном чтении журнала.
5. Если новая наблюдаемая попытка CONNECTING / AUTHENTICATING / RTC_CONNECTING
   зависла на 25 секунд без NO_ROUTE, включается ограниченное восстановление.
6. Состояния RTC продолжают считываться во время диагностики / обновления списков,
   но переключение откладывается до завершения занятой операции.
7. В диагностике появилась отдельная строка «Приём чужого эфира».
   Она показывает только счётчики из свежего локального журнала: видеопакеты,
   байты, декодированные кадры. RTC_CONNECTED и API не засчитываются как картинка.
8. Из готового пакета исключены 19 неиспользуемых Lua-скриптов и их импорты.
   Для правил нужны только zapret-lib.lua, zapret-antidpi.lua и наш core-rtc.lua.

КАК ПРОВЕРИТЬ ЧЁРНЫЙ ЭКРАН

1. Полностью выйдите из старой версии через трей. Крестик только скрывает окно.
2. Распакуйте весь новый ZIP в новую папку. Не переносите старую папку Engine.
3. Запустите ZapretCore.exe версии 1.5.0 и включите защиту.
4. Откройте «Правила защиты» → «Discord RTC: голос и трансляции».
5. Нажмите «Совместимый режим эфира». Он использует чистое разделение media TLS
   без дополнительных TCP-фейков и ограниченные служебные UDP-фейки с TTL.
6. В Discord выйдите из просмотра и снова откройте чужую трансляцию.
   Если завис голосовой канал — переподключитесь к нему.
7. Если не помогло, вручную выберите «QUIC-шаблон / TLS disorder», примените RTC
   и переподключитесь. Применение перезапускает наш движок и может прервать сеть.
8. Для сравнения доступен «Прямое медиа без изменений (ручной тест)».
   Он не меняет RTC-служебные пакеты и TLS discord.media. Остальные правила сайтов
   остаются включены. Это проверка вмешательства программы, не VPN и не способ
   гарантированно обойти блокировку: на заблокированном маршруте он может не помочь.
9. Для эфира в браузере используйте ручные режимы. Локальная статистика и
   автоматическое наблюдение относятся к обычной установленной версии Discord.

ЧТО ПОКАЗЫВАЮТ СЧЁТЧИКИ ЭФИРА

«Нет видеопакетов» — в свежей записи эфира ноль видеопакетов / байтов.
Это не доказывает неисправность видеодекодера; отправитель мог ещё не передать кадр.
«Кадры не декодированы» — пакеты есть, но счётчик кадров нулевой.
По этим данным нельзя отличить проблему ключей, кодека, декодера и паузу потока.
«Есть декодированные кадры» — в журнале есть ненулевой накопленный счётчик.
Это не гарантия непрерывного воспроизведения всех чужих эфиров.
«Данные устарели» / «Нет данных эфира» — текущий просмотр не подтверждён.
Если видеопакеты действительно идут, но картинки нет, сетевые стратегии не могут
сами починить графический драйвер / декодер Discord. Не отключайте шифрование.

АВТОВОССТАНОВЛЕНИЕ

По умолчанию включено для Discord на ПК. Учитывает только новые локальные события.
Не больше двух альтернатив за цикл; прямой режим в автоматический перебор не входит.
Между переключениями минимум 10 секунд, на подтверждение режима до 45 секунд.
Режим сохраняется после RTC_CONNECTED того же соединения и 5 секунд без разрыва.
Это состояние соединения, а не независимое подтверждение звука / видеокадров.
Если успех не подтверждён, возвращается прежний режим и делается пауза 5 минут.
Бесконечного перезапуска, входа в аккаунт и автоматического присоединения к звонкам нет.
Старые записи журнала при запуске не проигрываются. Если Discord уже завис до
включения программы, переподключитесь один раз, чтобы появилась новая попытка.

ПРОВЕРКИ И ГРАНИЦЫ

Нативные тесты WinDivert проверяют синтетические IPv4 и IPv6: RTP/RTCP обоих
направлений не захватываются, Discovery/STUN/DTLS и QUIC Initial захватываются.
Проверяются Lua-бюджет, прямой режим без fake, все TLS-варианты, обработка
NO_ROUTE + DISCONNECTED, зависание попытки, отложенные действия и счётчики видео.
Сетевые пробы API/Gateway и публичного STUN не являются проверкой чужого эфира.
Фактический просмотр и голос в пустом / многолюдном каналах требуют проверки
в вашем аккаунте. Обещания, что RTC больше никогда не зависнет, эта версия не даёт.
Happ, маршруты, прокси Windows, DNS Windows, брандмауэр, аккаунт и настройки
кодеков / шифрования Discord не изменялись.

ЧИСТЫЙ ИСХОДНИК ДЛЯ GITHUB

Публикуется новый ZapretCore, его тесты и необходимые скрипты / документация.
Старый большой ZapretUI, админ-панели, FTP-настройки, мобильные проекты,
история старого репозитория, журналы, пользовательские настройки, bin / obj,
старые ZIP и прочие приложения в чистый репозиторий не включаются.
Первоначальный каталог со смешанным исходником не удаляется.

Нативный комплект, предоставленный локально (winws2.exe / DLL / драйвер),
не загружается в Git автоматически. Он подключается локально через скрипт
Import-Engine.ps1 с проверкой SHA-256. Причина: отдельные сторонние компоненты
и модифицированные локальные сборки требуют установленного происхождения
и соответствующих исходников / уведомлений перед публичным распространением.
CI без комплекта проверяет сборку интерфейса и управляемые тесты. Полные нативные
тесты и готовый рабочий ZIP собираются локально после импорта комплекта.

СБОРКА

Нужен .NET SDK 9.x, Windows 10/11 x64. Готовый пакет включает runtime.
После подготовки Engine:
  dotnet build .\ZapretCore\ZapretCore.csproj -c Release
  dotnet test .\tests\ZapretCore.Tests\ZapretCore.Tests.csproj -c Release
  powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Build-CoreRelease.ps1 -Version 1.5.0
Готовое: artifacts\ZapretControl-1.5.0 и ZIP рядом.
Без нативного комплекта (только проверка кода, не рабочий DPI-пакет):
  dotnet build .\ZapretCore\ZapretCore.csproj -c Release -p:CoreIncludeEngine=false
  dotnet test .\tests\ZapretCore.Tests\ZapretCore.Tests.csproj -c Release --filter "Category!=NativeEngine"

Основной код: CoreProfileCatalog.cs, RtcStrategies.cs, RtcRecoveryCoordinator.cs,
DiscordRtcLogReader.cs, DiscordMediaEvidence.cs и MainWindow.Rtc.cs.
Настройки: %LOCALAPPDATA%\ZapretCore\settings.json
Журналы движка: %LOCALAPPDATA%\ZapretCore\logs
